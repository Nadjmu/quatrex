Block Thomas Error Analysis

What the two growth factors actually measure, where the Schur complements enter the bound, and what had to be built before the forward error could be compared against κ · backward error.

Solvers Block Thomas (LU) · Block Thomas (inv) · SuperLU · UMFPACK · MUMPS · cuDSS Materials carbon-nanotube, carbon-chain Reference Higham, ASNA, ch. 9 & 13
The ask

The question, as it was put

“I want to compare my custom implementation of Block Thomas in the LU based and Inverse based to the SuperLU MUMPS and cuDSS solvers. I think I already have a script which computes the growth factor. Explain me there the differences between the two growth factors. I think the one is normwise and the other is componentwise (tighter) but you gave it a weird name.”

“From what I understand LU backward error analysis is mainly bounded by the growth factor and a dimension dependent constant … The block thomas one shouldn’t be as stable as the others due to no pivoting. I then want to compare the forward error and see how well it is bounded by condition × backward_error. For the block thomas there is also I think some more growth factors due to the schur complements but I don’t understand that so well yet.”

The premise about the bound is right. Three things in the framing were not, and one quantity the chapter needs did not exist yet.

Correction 1

Both growth factors are normwise

loose and tight are not a normwise/componentwise pair. That distinction belongs to the two backward errors the benchmark already measures per solve — eta (Rigal–Gaches, normwise) and omega (Oettli–Prager, componentwise). The growth columns differ only in how much of the entrywise theorem each one throws away:

|A − LU| ≤ γn |L| |U| entrywise, Higham Thm 9.3 ⇒ ‖A − LU‖ ≤ γn ‖ |L||U| ‖ any monotone norm → tight ⇒ ‖A − LU‖ ≤ γn ‖L‖ ‖U‖ submultiplicativity → loose

So tight ≤ loose always, and it is tight that bounds the backward error of the factorization. loose is kept because it is the form usually quoted, and the gap between the two is itself worth showing.

The metric hierarchy, per (index, solver, precision, norm)
ColumnDefinitionRole
rho max|Uij| / max|Aij| Norm-free scalar. The cheap surrogate for Wilkinson’s max over all intermediate A(k).
tight ‖ |L||U| ‖ / ‖A‖ The quantity in the bound. Backward error ≲ γn × tight.
loose ‖L‖ ‖U‖ / ‖A‖ Upper bound on tight. Never smaller; sometimes by orders of magnitude.
resid_rel ‖A − LU‖ / ‖A‖ Not a stability metric. A guard that the assumed factor convention still holds.
Do not conflate

Growth is a property of the pivoting and is independent of κ(A). An ill-conditioned A may factor with negligible growth; a well-conditioned A may grow badly. Conditioning bounds the forward error; growth bounds the backward error.

Correction 2

Where the Schur complements enter

Block Thomas is block LU, and the three columns above only see the assembled global factors, not the recursion that produced them. The recursion is

S1 = A11, Sk = Akk − Ak,k−1 Sk−1−1 Ak−1,k the Sk are exactly the diagonal blocks of U_global (stored as Dmod)

Two facts govern it, and they are independent of each other and of κ(A):

  • Growth. maxk ‖Sk‖ / maxk ‖Akk‖ is the block analogue of rho. There is no pivoting across blocks to hold it down.
  • Conditioning of the pivot blocks. Block LU’s backward error carries κ(Sk), not just ‖Sk‖. A near-singular leading principal block submatrix makes some Sk near-singular however well conditioned A is and however little anything grew. Varah’s block diagonal dominance is the classical sufficient condition for this not to happen.

Why the two implementations must separate

Implementation 1 solves with Sk — backward stable per block. Implementation 2 forms Sk−1 explicitly, and explicit inversion is not backward stable: the computed inverse satisfies only

‖ S G − I ‖ ≲ c · u · κ(S)

So implementation 2 pays a factor maxk κ(Sk) that implementation 1 does not. That is the quantitative statement the chapter was missing, and it is now measured directly as inv_resid_max. A synthetic block-tridiagonal check reproduces the theory to within a factor of two:

κ2(Sk) = 3.1e1, six blocks

The gaps

What blocked the chapter as framed

Four obstacles, three of them fixed by new code and one that reshapes how the comparison has to be presented.

Structural

MUMPS and cuDSS expose no factors

python-mumps’ Context API has no .L/.U, and cuDSS is the same. Neither can appear on a growth-factor plot.

The chapter is therefore two comparisons: growth factors for the four solvers that expose factors (UMFPACK replacing MUMPS as the globally pivoting reference), and measured η/ω plus forward error for all six.

Fixed

No valid forward-error reference

The stored vs_base is measured against the SuperLU complex128 solution, which carries an error of the same order as the solutions being judged. At complex128 it compares two errors of equal size.

Replaced by iterative refinement with an extended-precision residual.

Fixed

No Skeel condition number

κ∞ pairs with the normwise η. The tight pairing is cond(A,x) · ω, and cond(A,x) is often orders of magnitude below κ∞.

Added to the condition sweep, estimated from the LU already computed there.

Fixed

The recursion was invisible

Nothing measured the Schur complements, so the two Block Thomas variants had no predicted separation to be checked against.

Four columns added, computed from factors already on disk.

The bounds

The two pairings the chapter tests

‖x̂ − x‖∞ / ‖x‖∞ ≲ κ∞(A) · η∞ normwise ‖x̂ − x‖∞ / ‖x‖∞ ≲ cond(A,x) · ω componentwise, sharper cond(A,x) = ‖ |A−1||A||x| ‖∞ / ‖x‖∞

Everything on the right already existed. The left-hand side is what the new forward_error.py supplies: a reference solution obtained by refining the complex128 solution with the residual accumulated in np.clongdouble (80-bit, eps = 1.1e-19) and the correction solved with the same double factorization. SciPy has no sparse type in that precision, so A x̂ is formed from the CSR arrays directly and summed per row with np.add.reduceat.

Known limit, recorded not hidden

Refinement in residual precision u_r converges to an error of order κ · u_r, so the reference beats a double solution by about 2e3 — not by the u² a true double-double residual would give. ref_floor = κ∞ · eps_ext is written per index, and any forward error within an order of magnitude of it measures the reference, not the solver. For complex64 and complex32 the separation is ample; at complex128 it closes once κ∞ approaches 1/eps_ext.

Run order

How to produce the chapter

Per material. Steps 1 and 2 are independent of each other; 3 needs both. No step takes a block size — the partition is detected from the sparsity pattern — and none takes an index range: with no selection each sweeps whatever the file holds, so --stride is how a first pass is shortened.

  1. Skeel columns onto the existing condition sweep

    python condition-est/condition_est.py --material carbon-nanotube --only-skeel

    Reuses the valid rows; no singular values, so it is far cheaper than a full rerun.

  2. Growth factors, including the Schur recursion

    python block-thomas/growth_factor.py .../carbon-nanotube.h5 --stride 10 \
    --solvers block-thomas block-thomas-inv superlu umfpack

    Cost scales with block size: one SVD per diagonal block per (solver, precision).

  3. Forward errors, all six solvers

    python block-thomas/forward_error.py .../carbon-nanotube.h5 --stride 10

    One factorization and a few refinement steps per index. Try --idx 25 --no-save first to time it.

  4. Figures

    python plotting/block-thomas/plot_growth_factor.py .../carbon-nanotube.h5
python plotting/block-thomas/plot_forward_error.py .../carbon-nanotube.h5

    Written beside the data they were drawn from, in error-analysis-block-thomas/.
