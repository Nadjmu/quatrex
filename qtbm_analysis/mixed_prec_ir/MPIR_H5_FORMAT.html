What mpir.py writes

Every invocation of mpir.py appends one numbered experiment to a per-material HDF5 file — its full configuration as group attributes, and two tables: one row per solver variant, one row per outer refinement step. Nothing is ever overwritten.

File layout

One file per material, at <outdir>/<material>/<material>.h5 (analysis_path). --no-save skips writing entirely.

<material>.h5 └── experiments/ ├── 0001/ # attrs: the whole run configuration │ ├── runs # one row per (idx, variant) │ └── iterations # one row per (idx, outer refinement step) ├── 0002/ └── ...

Group names are zero-padded so HDF5's string-key ordering matches numeric order. The lowest unused number is reused if an experiment is deleted by hand.

Why some quantities carry a hat

^

x_true is a numerical reference solution, from --reference-solver, not the exact answer. So mu_hat, phi_cond_hat, phi_solve_hat and phi_hat are estimates, not certified bounds.

See refinement_metrics in mpir.py for the full derivation, and Carson and Higham, A new analysis of iterative refinement and its application to accurate solution of ill-conditioned sparse linear systems, SIAM J. Sci. Comput. 39(6), 2017, Corollary 3.3.

Reading it back

Both tables come back as column dicts, {column_name: numpy_array}, from factor_io.load_table.

from mpir import load_experiment

# last experiment in the file
name, attrs, runs, iters = load_experiment("/path/to/material.h5")

# a specific one, by number
name, attrs, runs, iters = load_experiment("/path/to/material.h5", experiment=3)

mpir.py --list-experiments <h5path> prints a one-line summary of every experiment in a file without loading either table.
